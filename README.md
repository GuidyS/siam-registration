# Siam Registration Assistant — v2 Demo

รายละเอียด UI ปรับตามแนวทาง [Unslop](.agents/skills/unslop/SKILL.md) โดย Damir Sokolovsky ([@heydamir](https://x.com/heydamir)) ภายใต้ [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)

เว็บสาธิตสำหรับคำถามเรื่องเพิ่ม–ถอนรายวิชา ใช้ข้อกำหนดจาก [สกิลในโปรเจกต์](.agents/skills/siam-registration-builder/SKILL.md) Student Chat และ Staff Live Chat เชื่อมกันผ่าน API และฐานข้อมูลเดียวกัน ไม่มีการแก้ไขการลงทะเบียนรายวิชาจริงหรือเชื่อม LINE

## โครงสร้างโปรเจกต์

```text
frontend/          หน้าเว็บและโค้ดที่รันในเบราว์เซอร์
  index.html
  src/             JavaScript และ CSS ของหน้าเว็บ
backend/           Node.js API และคำตอบเดโม
data/              ฐานข้อมูล SQLite ที่สร้างตอนรัน
test/              API flow tests
vite.config.js     ตั้งค่า Vite และ proxy ไปยัง API
```

เวลาอธิบายงาน: Vite ให้บริการหน้าเว็บใน `frontend/` ส่วน API และการอ่านเขียน SQLite อยู่ใน `backend/` ข้อมูลตัวอย่างจริงอยู่ใน `data/`.

## เริ่มใช้งาน

ต้องมี Node.js 24 ขึ้นไป ติดตั้งแพ็กเกจและเปิดเว็บพร้อม API ในโหมดพัฒนาได้ด้วย Vite

```bash
npm i
npm run dev
```

เปิด URL ที่ Vite แสดง (ปกติคือ <http://localhost:5173>) เพื่อดูหน้า v2 ระบบเข้าเดโมเป็น `student1` ให้อัตโนมัติ กด **นักศึกษา/เจ้าหน้าที่** มุมขวาบนเพื่อสลับเป็น `student1` หรือ `staff1` ตามบทบาท ข้อมูลแต่ละบทบาทยังผ่าน API และฐานข้อมูลเดียวกัน บัญชี `student2` และ `staff2` ยังมีไว้สำหรับทดสอบ API

สร้างไฟล์สำหรับ build ด้วย `npm run build` ส่วน `npm start` ยังคงเปิดเว็บและ API ผ่าน Node.js โดยตรงที่ <http://127.0.0.1:3000>

```bash
npm test
```

ข้อมูลอยู่ที่ `data/app.sqlite` และคงอยู่หลังรีสตาร์ตเซิร์ฟเวอร์ โฟลเดอร์ `data/` ถูกละเว้นจาก Git ตั้งค่า `PORT` และ `DATA_DIR` ได้ถ้าต้องการเปลี่ยนพอร์ตหรือที่เก็บข้อมูล เซิร์ฟเวอร์ฟังเฉพาะ `127.0.0.1`

## สิ่งที่ทำได้

- นักศึกษาถามผู้ช่วยเดโม เพิ่ม–ถอนรายวิชาทดสอบ สร้างคำร้อง รับ/ยกเลิกคิว และดูสถานะคิวกับคำร้องของตน
- เจ้าหน้าที่รับคิว ดูบริบทเดิม ตอบในบทสนทนาเดียวกับนักศึกษา และปิดงาน
- เมื่อเจ้าหน้าที่ปิดบทสนทนา นักศึกษากด **เริ่มแชตใหม่** เพื่อถาม AI ต่อได้
- ข้อความและสถานะเก็บใน SQLite; หน้าเว็บดึงข้อมูลใหม่ทุก 3 วินาที
- API ตรวจบทบาทและเจ้าของข้อมูล; การรับคิวใช้การอัปเดตแบบมีเงื่อนไขเพื่อกันเจ้าหน้าที่รับซ้ำ

## ขอบเขตเดโม

คำตอบอัตโนมัติใช้ [ชุดคำตอบตัวอย่าง](backend/demo-knowledge.js) สำหรับวิธีเพิ่ม วิธีถอน ปัญหาที่พบบ่อย และการติดต่อเจ้าหน้าที่ ทุกคำตอบระบุว่าเป็นข้อมูลทดสอบ และคำถามเรื่องกำหนดวันหรือค่าใช้จ่ายจะไม่สร้างข้อมูลขึ้นมา ปุ่มเพิ่ม–ถอนอยู่กับคำถามลัดในหน้า AI Chatbot เมื่อกดจะแสดงช่องค้นหารหัสวิชาในพื้นที่แชต เช่น `101-101` และ `201-201` เมื่อพบจะแสดงชื่อและปุ่มเพิ่ม รายการที่เพิ่มบันทึกใน SQLite ของเว็บนี้เท่านั้น ไม่เชื่อมระบบลงทะเบียนจริง ยังไม่มี RAG หรือแหล่งประกาศที่อนุมัติแล้ว คำร้องสร้างและติดตามได้ แต่ยังไม่มีหน้าจอเจ้าหน้าที่สำหรับจัดการคำร้องโดยตรง Live Chat ใช้ polling แทน WebSocket และบัญชี/รหัสผ่านที่แสดงไว้มีไว้สำหรับเดโมในเครื่องเท่านั้น ก่อนใช้งานจริงต้องเชื่อมระบบยืนยันตัวตนของมหาวิทยาลัย แหล่งความรู้ที่รับรอง และกำหนดนโยบายข้อมูลส่วนบุคคล/การเก็บรักษา
